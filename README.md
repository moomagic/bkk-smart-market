# BKK Smart Market — prototype

ระบบต้นแบบบริหารการขอใช้และจัดสรร **พื้นที่ค้าขายเดิมที่ กทม. อนุญาตแล้ว** ให้เข้าถึงง่าย โปร่งใส และเป็นธรรม
Pilot: เขตบางพลัด · **ข้อมูลทั้งหมดเป็นข้อมูลจำลอง** · ระเบียบใน `docs/rules/` เป็นระเบียบตัวอย่าง ไม่ใช่ระเบียบจริงของ กทม.

## รันด้วยคำสั่งเดียว

ต้องมี Docker (Compose ≥ 2.17) เท่านั้น — image รันได้บน arm64 (Apple Silicon) และ amd64

```sh
docker compose up --build
```

| URL | |
|---|---|
| http://localhost:8080 | เว็บ (`/vendor` ผู้ค้า · `/portal` เจ้าหน้าที่เขต · `/dashboard` ผู้บริหาร) |
| http://localhost:8080/docs | API reference (OpenAPI + Scalar) — ส่ง header `X-Demo-Role` / `X-Demo-User` |

ครั้งแรก API สร้างฐานข้อมูล, seed ข้อมูลจำลอง และประวัติรอบก่อน (จับฉลากด้วย engine จริง) ให้เอง

### Environment (ไม่บังคับ)

ใส่ในไฟล์ `.env` ที่ root (git-ignored — ห้าม commit) แล้ว `docker compose up` จะอ่านเอง

| ตัวแปร | ค่าเริ่มต้น | |
|---|---|---|
| `ANTHROPIC_API_KEY` | ว่าง | มี key → Vendor Assistant ตอบผ่าน Claude · ไม่มี → keyword match กับหัวข้อใน `docs/rules/` |
| `ANTHROPIC_MODEL` | `claude-opus-5-5` | model ที่ Assistant ใช้ |

ค่าอื่นอยู่ใน `api/src/SmartMarket.Api/appsettings.json`: กติกาทั้งหมดอยู่ใต้ `Rules` · เวลา demo เริ่มที่ `Demo:Now` = 25 ต.ค. 2569 09:00 (อยู่ในช่วงเปิดรับคำขอ)

## Demo script

บทบาทสลับได้ที่มุมขวาบน (auth จำลอง) — ใน `/vendor` อยู่ในปุ่ม **เดโม** บนแถบหัวของแอป · ผู้ค้าเริ่มต้นคือ **สมศรี ใ.** (ขายข้าวแกง เคยได้ล็อคที่ปากซอยจรัญฯ 79 รอบก่อน)

`/vendor` เป็นแอปมือถือ: แท็บล่าง **คำขอ · หาพื้นที่ · ถามระเบียบ** · กดคำขอเพื่อเปิดหน้ารายละเอียด (ปุ่มยืนยัน/สละ/เช็คอินอยู่ด้านล่าง · ← ย้อนกลับ) · บนจอกว้างแสดงในกรอบมือถือ 390px กลางจอ

1. `/vendor` (เปิดที่แท็บ **คำขอ**: "สวัสดี สมศรี ใ." · รับคำขอรอบใหม่ถึง 31 ต.ค. 2569) → แท็บ **ถามระเบียบ** → **ต้องใช้เอกสารอะไร** → ได้คำตอบพร้อม "อ้างอิง: documents.md › …"
2. แท็บ **หาพื้นที่** → ขาย **ข้าวแกง** · ย่าน **จรัญฯ** → **แนะนำพื้นที่** → ปากซอยจรัญฯ 79 อันดับ 1 (90/100) → **ยื่นคำขอที่นี่** → เปิดหน้าคำขอ สถานะ "ยื่นคำขอแล้ว" · รอเขตตรวจสิทธิ
3. ปุ่ม **เดโม** → สลับเป็น **เจ้าหน้าที่เขต** → `/portal` → รายการรอบด้านซ้าย: **ปากซอยจรัญฯ 79** (รอบ 1 พ.ย. 2569 · เปิดให้เองเมื่อมีคำขอรอตรวจ) → **ตรวจสิทธิทั้งรอบ** (ชัย ด. ไม่ผ่าน: ยังไม่อบรมสุขาภิบาล · ปิยะ น. น้ำหนัก ×2) → **รันจัดสรร** → แท็บผลจัดสรร: โควตา 2/1/1 + เลขอ้างอิง `BPL-2569-1025-01` + เลขตั้งต้นการสุ่ม (seed) · ค่าแฮชข้อมูลนำเข้าอยู่ใต้ "หลักฐานการสุ่ม" → **อนุมัติผล** (ท้ายผลรายคน) → dialog ทวนผล → **ยืนยันอนุมัติผล**
4. ปุ่ม **เดโม** → สลับเป็น **ผู้ค้า** → แท็บ **คำขอ**: "ยืนยันสิทธิ์ล็อค **B2** ภายใน …" (แท็บคำขอมีจุดเตือน) → กดคำขอ → "ได้ล็อค **B2**" พร้อมเหตุผลและเลขอ้างอิง → **ยืนยันสิทธิ์** → **สแกน QR เช็คอินที่ล็อค B2**
5. ปุ่ม **เดโม** → สลับเป็น **เจ้าหน้าที่เขต** → `/portal` → เลือกรอบ **ปากซอยจรัญฯ 79** → **ประวัติการดำเนินการ** (เปิดเป็นแผงด้านขวา) → เห็นทุกขั้น: ยื่นคำขอ → ตรวจสิทธิ → รันจัดสรร → อนุมัติ → ยืนยัน → เช็คอิน (ข้อมูลส่วนบุคคลเป็น `***`)
6. สลับเป็น **ผู้บริหาร** → `/dashboard` → Occupancy เพิ่มขึ้น 1 ล็อคจากก่อนเริ่ม (88.6% → 91.4%)
7. ทั้งหมดนี้มาจาก `docker compose up` คำสั่งเดียว

**เดินซ้ำ:** `/portal` → ปุ่ม **เวลา demo …** มุมขวาของหัวหน้า → **เริ่ม demo ใหม่** (กดสองครั้ง) หรือ `POST /api/demo/reset` — ลบทุกตารางแล้วสร้างใหม่เหมือนติดตั้งครั้งแรก (audit trail เดิมหายด้วย และเริ่มใหม่ด้วยรายการ reset) เวลากลับเป็น `Demo:Now` แล้วสมศรีจะได้ B2 อีกครั้ง (Development เท่านั้น)

ปุ่ม **+1 วัน / +4 วัน** (อยู่ในปุ่ม **เวลา demo …** ของ `/portal`) เลื่อนเวลา demo — เช่น +4 วันหลังอนุมัติ ผู้ได้สิทธิ์ที่ยังไม่ยืนยันจะถูกสละสิทธิ์และสำรองเลื่อนขึ้น

## สูตร KPI (`/dashboard`)

ทุกพื้นที่นับ **รอบล่าสุดที่มีผลจัดสรรอนุมัติแล้ว** · ผู้ได้สิทธิ์ = คำขอสถานะ Won หรือ Confirmed ตอนนี้

| KPI | สูตร |
|---|---|
| Occupancy | ล็อคที่ผู้ได้สิทธิ์ยืนยันแล้ว ÷ ล็อคทั้งหมด |
| LeadTime | มัธยฐานจำนวนวันจากปิดรับคำขอ → อนุมัติผล (อนุมัติก่อนปิดรับ เช่นใน demo นับ 0) |
| NewVendors | ผู้ได้สิทธิ์กลุ่มผู้ค้าใหม่ ÷ ผู้ได้สิทธิ์ |
| FairRotation | ผู้ได้สิทธิ์ที่ไม่ได้ถือล็อคที่พื้นที่เดียวกันรอบก่อน ÷ ผู้ได้สิทธิ์ (ผู้ได้สิทธิ์หน้าใหม่ + ผู้ได้น้ำหนัก ×2) · **ส่วนที่ต่างจาก spec:** พื้นที่ที่ไม่มีรอบก่อนในระบบ นับทุกคนที่ไม่ใช่กลุ่มผู้ค้าเดิม เพราะกลุ่มผู้ค้าเดิมหมายถึงเคยได้สิทธิ์ที่นี่รอบก่อน |

## กติกาที่ implement

ตามตาราง Business rules ใน `CLAUDE.md` และ ADR ใน `docs/adr/`

- **ทำจริง:** คุณสมบัติ 3 ข้อ · 1 คน 1 คำขอที่ยังไม่จบต่อช่วงรอบที่ทับกัน (ADR-0003) · พื้นที่ทดลองค้า 1 ครั้ง/ปี · โควตา + โอนโควตา + น้ำหนัก ×2 + สำรอง 3 คน/กลุ่ม (ADR-0001) · seed จากระบบ + ตรวจย้อนได้ (ADR-0002) · ปฏิเสธผลต้องมีเหตุผล ≤ 2 ครั้ง/รอบ เกินนั้นผู้บริหาร · ยืนยันภายใน 3 วัน ไม่ยืนยัน = สละสิทธิ์ (คำนวณตอนอ่าน · ADR-0004) · เช็คอิน QR · ขอทบทวนผล (ADR-0005) · audit ทุก command
- **ธงอ่านอย่างเดียว (Allocation Insight · `/portal` เมื่อเลือกรอบ):** เช็คอิน < 80% ของวันขายในเดือน · ไม่เช็คอิน 7 วันขายติด (เตือน) / 14 วันขายติด (ถึงเกณฑ์ยกเลิกสิทธิ์ แต่ระบบ**ไม่ยกเลิกเอง** เจ้าหน้าที่ตัดสิน) · เช็คอินนอกพื้นที่ · ผู้ได้สิทธิ์นามสกุลหรือเบอร์ซ้ำกัน — นับเป็น "วันขาย" ตามเวลาทำการของพื้นที่ (ตลาดนัด ศ–อา: 14 วันขาย ≈ 5 สัปดาห์) และยังไม่มีบันทึกการแจ้งหยุด จึงนับการขาดทุกครั้ง
- **ยังไม่ implement (อยู่ใน config + `docs/rules` เท่านั้น):** ต่อสิทธิ์ต่อเนื่องสูงสุด 2 รอบ · ยกเลิกสิทธิ์และงดสมัครเมื่อพบการเช่าช่วง · ยกเลิกสิทธิ์จากการขาด (มีแค่ธงให้เจ้าหน้าที่)

## ข้อจำกัดของระบบต้นแบบ

- **ไม่ใช่ระบบจริง:** auth จำลองด้วย header (`X-Demo-Role`, `X-Demo-User`) · QR และ geofence จำลอง · ไม่เชื่อมต่อ LINE/LIFF, ThaiMarket, BMAOSS หรือ Traffy · ไม่มีการชำระเงิน
- **นาฬิกา demo:** ทุกกติกาอ่านเวลาจาก `Demo:Now` ที่เลื่อนได้ · demo จับฉลากและเช็คอินก่อนวันเริ่มรอบได้เพื่อให้เดินจบในวันเดียว
- **การกดพร้อมกัน:** การยื่นคำขอและการตอบคำขอทบทวนทำทีละคำสั่งต่อผู้ค้า (กฎ 1 คน 1 คำขอไม่หลุด) · คำสั่งที่ชน unique index (รันสองครั้ง, เช็คอินซ้ำวัน ฯลฯ) ได้ 409 "ลองใหม่" แทน 500 · ยังไม่กัน: อนุมัติ/ปฏิเสธ/ยืนยันแถวเดียวกันพร้อมกัน (ไม่มี concurrency token อาจผ่านทั้งคู่) และการสละสิทธิ์อัตโนมัติ (ADR-0004) ที่เกิดจากการอ่านสองครั้งพร้อมกัน
- **Vendor Assistant:** ตอบจาก `docs/rules` เท่านั้น การกันคำถามเรื่องผลของบุคคลใช้คำในประโยค (มี system prompt กันอีกชั้นเมื่อใช้ Claude)
- **ทบทวนผล:** แก้ได้เฉพาะผลตรวจสิทธิที่ไม่ผ่าน · น้ำหนักผิดของคำขอที่ผ่านแล้วแก้ผ่านการทบทวนไม่ได้ · กำหนดตอบ 7 วันแสดงแต่ไม่บังคับ
- **Dashboard:** ปากซอยจรัญฯ 79 รอบก่อนเป็นข้อมูลเขียนมือ ไม่มีผลจัดสรรในระบบ จึงนับ 0 จาก 4 ล็อคจนกว่ารอบใหม่จะอนุมัติ
